# Code Tycoon

Live isometric city of a project's code plus the Claude Code sessions working in it.
Server: `server/` (Node 22, built-in `node:sqlite`, `ws`). UI: `web/` (Vite + TS + Three.js).
Data: `~/.codetycoon/codetycoon.db`. Hook script: `~/.codetycoon/hook.mjs` (copied by `npm run hooks:install`).

- `npm run dev` — API on :4400 + Vite on :5173 · `npm run build && npm start` — everything on :4400
- `PID=<tracked project id, e.g. c:/users/archi/downloads/visualizer> node scripts/probe.mjs probe-out` — screenshots + fps + console errors (uses installed Chrome; exits without `PID`)
- `node scripts/live-test.mjs <demo repo>` — two real sessions edit one file, expects a collision alert

Renamed from Visualizer on 2026-11-16: settings are `CODETYCOON_*`, data `~/.codetycoon`, hook header `x-codetycoon-token`, launcher `CodeTycoon.vbs`. Old names still work only as fallbacks (`server/env.mjs`, `dataDir()` in paths.mjs, `dbFile()` in db.mjs, `OWN_DIR_RE`); write new code with the new names. The repo folder and project id are still `.../Visualizer`.

This repo is public (AGPL): the local, single-user app only. Anything for the hosted/managed service (accounts, work containers, deploy, server details) goes in the private repo next to this folder (`../hosted-code-tycoon`), never here.

## Known Pitfalls

- `node:sqlite` does not support repeated numbered params (`?1` used twice → "column index out of range") — use named params (`$pid`) and pass an object.
- SQLite `MIN(x, NULL)` is NULL, so `first_ts=MIN(first_ts, ?)` wiped values when a chunk had no timestamp — wrap with `COALESCE(..., first_ts)`.
- `claude -p ... --allowedTools A,B "<prompt>"`: `--allowedTools` is variadic and swallows the prompt ("Input must be provided") — send the prompt on stdin.
- The `claude` CLI is not on PATH here; it lives in `~/.vscode/extensions/anthropic.claude-code-<ver>-win32-x64/resources/native-binary/claude.exe` and the folder changes on every update — resolve it at runtime (`findClaudeCli()`).
- Summarizer calls must use `--no-session-persistence --setting-sources project` from `~/.codetycoon/summarizer`, or they write transcripts and fire hooks and Code Tycoon draws its own summarizer.
- Parallel Claude sessions edit this repo at the same time (one rewrote `world.ts` minutes after another session edited it, silently dropping those edits). Before a build or restart, grep your own changes back out of the files and check mtimes. If another session is mid-refactor, stop and coordinate.
- Playwright's bundled headless shell is not downloaded on this machine — launch with `channel: 'chrome'`.
- `/hook` rejects posts without the `x-codetycoon-token` header (token in `~/.codetycoon/token`). After changing the hook or the server's checks, re-run `npm run hooks:install` together with the restart, or every hook event is dropped with a silent 403.
- Session cards are rebuilt on every `session` message, so a hovered card can be replaced under the cursor and its `mouseleave` never fires — anything tied to hover state belongs on the list container, not the card.
- `npm run build` (Vite) does not type-check and ships code with TS errors (e.g. a local `h` shadowing the `h()` helper) — run `npx tsc --noEmit -p .` from the repo root (no tsconfig in `web/`) before building.
- An element hidden by a CSS rule (`display: none`) stays hidden when its inline style is set to `''`; set an explicit value (`'block'`) to show it.
- A side Vite server (`npx vite --port 5191`, for testing without restarting :4400) listens on `localhost` (IPv6) only; `127.0.0.1:5191` is refused. Point probes at `http://localhost:5191`. Start it from the repo root (`vite.config.ts` lives there, `root: 'web'`); run from `web/` it has no `/api` proxy and the page never loads.
- Layer classes in `styles.css` are generic and global (`.schematic`, `.stage`); using one as a modifier (`ly-thumb schematic`) pulled in `position:absolute; inset:0`. Don't reuse them as modifier class names.
- `node --experimental-strip-types` rejects TS parameter properties (`constructor(public x)`); use `--experimental-transform-types` to run a `.ts` module directly.
- Districts are roles, not graph communities: `server/roles.mjs` + `assignRoles` in `summarize.mjs` (kv `roles:<pid>`); a folder split across roles yields several modules with the same `id` — use `m.key` when you need a unique module id.
- Block and district properties (Database: engine/tables/migrations, Payments: providers/currencies…) are regex detectors per role in `server/traits.mjs` (`KINDS`); a project-specific district borrows a kind by name via `kindOf()`. Add a property there, not in the UI; `propsSection()` in `cityview.ts` renders whatever comes back.
- District looks are a closed catalog: `STYLES` + `styleOf()` in `server/roles.mjs` (summarizer picks one per project district, keywords and a hash fall back), drawn by `city/themes.ts` (facades, roof pieces), `city/dressing.ts` (props, parks, river/rail/airfield) and `city/life.ts` (people, vehicles). Add a new look to all three, not just the server list.
- Domain map (`domain.ts`): `layout()` places isles and the real-world ring together (relations, flow hops, ties down) and hands `worldA` to `makeGround`; every line (bridge, tie down, flow) goes through `metroPath()` (schematic rules 8/9/12). Draw new lines with it, and frame views with `frameAll()` (exact screen-axis fit), not ground boxes.
- Roads are routed on a grid in `city/roads.ts` + `city/route.ts`; the schematic layer (`schematic.ts`) routes its own connectors with the same router. world.ts only holds hooks into them.
- `StreetGrid.corners()` + `port()` leave repeated/collinear points, which hide Z and L shapes from any shape test — run `collinear()` first (schematic rules 8-12 are the metro-map rules; keep new line drawing to them).
- Dragged places (areas, stores, towers) are kept per browser in localStorage `vz-layout:<pid>` and laid over the server layout by `applyLayout()` (`city/layout.ts`) right after `api.city()`. Any new code path that fetches the city must call it too, or the city and the schematic disagree with what the user arranged.
- The user views the app on :4400, which serves `dist/` — UI changes don't show until `npm run build` (static files are read per request, so no restart needed; server `.mjs` changes do need one).
- Git Bash's `/tmp` is not the `/tmp` node resolves (`require('/tmp/x')` → C:\tmp) — write scratch files to the session scratchpad and pass node a Windows path.
- Bash heredocs here collapse `\\` to `\` even with a quoted `'EOF'` (a patched `'\n'` became a real line break, a test regex broke) — write scripts and code with backslashes via the Write/Edit tools, then `node --check`. Same for `node -e` patches containing template literals (backticks/`${}` break bash quoting), and any heredoc whose body has quotes (`content: ''` → "unexpected EOF") — write the file with Write, never a heredoc.
- `python` is only the Windows `py` launcher stub here (prints usage, does nothing) — script file edits with `node` or the Edit tool.
- The `sessions` table only holds sessions of tracked projects (Code Tycoon itself is untracked); anything machine-wide (e.g. `server/idle.mjs` naming CLI processes) must also read `~/.claude/projects/*/*.jsonl` directly.
- A node process with no parent is often a daemon the user started on purpose (`~/.claude/mcp-gateway`, `sync-skills.js watch`, this server itself), not a leftover — idle detection only flags parentless helpers from `node_modules`/npx.
- `git add <file>` on a deletion already staged by `git rm` fails ("pathspec did not match") — chain every add/commit step with `&&` so a later `git add -A && commit` can't sweep everything into the wrong commit.
- `npm publish` here goes through npm's staged publishing: the registry shows a `0.0.0-stage` placeholder as `latest` until the real version is approved on npmjs.com (needs 2FA) — check `npm view <pkg> version` before telling anyone it's live.
- GitHub renders every `user-attachments/assets/...` URL in a README as a video player, even inside `<a href>` — put it only on its own bare line, never as a link target.
- A hand-written probe opening `localhost:4400/#/p/<raw pid>` without GPU args screenshotted a blank white page — copy `scripts/probe.mjs`: `127.0.0.1`, `encodeURIComponent(pid)`, the `--use-angle=d3d11 --enable-gpu --ignore-gpu-blocklist` args.
- A probe script in the scratchpad can't `import 'playwright'` (ERR_MODULE_NOT_FOUND) — import `file:///C:/Users/archi/Downloads/Visualizer/node_modules/playwright/index.mjs`.
- The schematic overview opens at scale ≈0.25: 12 world units are 3px on screen. Judge connector spacing (lanes, stubs, arrowheads) in screen px, not world units.
- `import('C:/...')` in a Windows node script fails (ERR_UNSUPPORTED_ESM_URL_SCHEME) — use `file:///C:/...`.
- The city opens at viewSize ≈ span×0.9 (≈250 for a mid-size repo), not the Stage default 60, and file buildings show up to viewSize 120. Pick zoom-gated effects' thresholds against those numbers and check them in a probe screenshot, or the effect never appears for the user.
- Prompts sent by `claude -p` are `turnOrigin: "sdk"` and the parser counts only human prompts, so scripted demo sessions give 0 tasks — for demo data, retag copies of the transcripts to `"human"` before indexing.
- Codex CLI sessions are a second source: `server/codex.mjs` parses `~/.codex/sessions/**/rollout-*.jsonl` (`event_msg` → `item_completed`) into the same items as `transcript.mjs`; `indexFile` branches on `isCodexFile`, slugs are `codex:<slug>`. A new source must emit the same item kinds, not new ones.
- `codex exec --full-auto` no longer exists, and on Windows both `-s read-only` and `-s workspace-write` block every command, reads included (codex 0.166) — to make a test rollout, use `--dangerously-bypass-approvals-and-sandbox` in a scratch repo.
- Every model call (titles, recaps, domain map, briefs, Optimize) goes through `runAgent()` in `server/llm.mjs`, which picks Claude Code or Codex (`CODETYCOON_LLM`) and maps models and sandboxes — never spawn `claude`/`codex` directly. Codex on Windows refuses read/edit jobs unless `CODETYCOON_CODEX_UNSANDBOXED=1` (reads then run in a temp copy).
- Another session's half-edited file (a TS syntax error) blanks the page on a side Vite too, and blocks `npm run build` — test with a scratch vite config whose plugin `load()` returns `git show HEAD:<file>` for that file; don't touch their file.
- Another session's side Vite may already hold :5191; Vite then silently takes the next port — read its "Local:" line before pointing a probe at it.
- Coaching (`server/coach.mjs`) caches each session's analysis keyed on its usage rows; anything that changes compactions or `res_len` without new API calls (a backfill) must call `resetCoach()`, or the overview keeps stale numbers.
- An isolated demo server (`USERPROFILE`/`HOME` = a fake home, `CODETYCOON_PORT=4401`, `CLAUDE_CONFIG_DIR` = the real `~/.claude` so titling still authenticates, `CODETYCOON_CLAUDE` = the real `claude.exe` or domain builds fail with "spawn claude ENOENT") keeps private projects off screen. `discover()` skips junctions (Dirent isn't a directory), so copy transcripts in; start it from outside the repo or its PowerShell sampler drops a `Microsoft/` cache folder into the cwd.
- README media (`docs/media`) scripts live outside the repo in `~/Downloads/demo/capture/` (README.txt there has the steps). The demo sessions are hours old by re-shoot time, so start the :4401 server with its `shift-clock.mjs` preload or the overview shows 0 open sessions and the timeline is empty.
- The UI chrome is black and white (tokens in `styles.css` `:root`; `--cyan/--green/--amber` now resolve to black, red is the only signal color). The city defaults to a light day to match (`sky.ts` `enabled=false` = always day; ground, grid, lots, plates and asphalt follow `ENV.night` via `World.tone()`/road shader; `.cityview.day` restyles labels). Open ground is grass (`groundMaterial()` in world.ts) and the woods/meadows around the city come from `wild()` in dressing.ts; the two use the same noise formula, change both together. The schematic canvas is light too (`NODE`/`COL` in schematic.ts, legend swatches `.lg-node` in styles.css, thumbnails in cityview.ts must agree). Don't bring tinted rgba fills back into panels.
- A Bash command with a bare `cat > file` (no heredoc/stdin) hangs until the 2-min timeout and nothing after it runs — never start a command with it; edit files with the Edit tool.
- `~/.codex/config.toml` holds MCP bearer tokens in `http_headers`; a `grep -v key|token` filter still printed one — read only the keys you need (`grep '^model'`), never cat or loosely filter config files.
- The `kv` table's columns are `k` and `v` (not key/value) — `SELECT k, v FROM kv WHERE k LIKE 'domain:%'`.
- Domain map cost: builds and updates run on `MAP_MODEL` (Sonnet), not the session's model (Opus updates cost dollars each). Updates default to the original full re-read; `CODETYCOON_DOMAIN_UPDATE=patch` switches to one tool-less turn over the diff returning a patch (`applyPatch()`, ~$0.17).
- The domain-map route is `/api/projects/<encoded pid>/domain` (not `/api/p/`) and reads the action from the path (`POST .../domain/update`, `/domain/stop`), not the body — a POST to `/domain` with `{"step":"update"}` starts a full rebuild (paid).
- `put(el, ...)` in util.ts appends, it does not replace — clear first (`el.replaceChildren()`) when re-rendering a panel, or every refresh stacks another copy.
- Toggling `material.transparent` on a live material does nothing until `material.needsUpdate = true` (the shader is recompiled) — opacity fades silently stay opaque.
- Snow was removed on purpose (it whitened roofs and lots until districts ran together); don't bring it back. Fog near/far follow the zoom in `Stage.updateCamera()` — a fixed fog paled the far half of the city.
- District lots must stay a clear tint by day (`DistrictGrounds.tone()`, lightness ≈0.6): sun + tone mapping push a 0.8-lightness tint to near white.
- Selection on the map is `World.selFrame()` → `city/highlight.ts` (ground frame + pin, sized per kind). HTML labels (session tags) sit right over building tops and hide anything 3D drawn there — keep selection cues on the ground or above the label.
- A side Vite reloads the page whenever another session saves a file, which wipes state injected via `window.__view` (fake drones) mid-probe. Inject and screenshot in one `evaluate` burst, or test real live sessions.
- Session colours are neon for the night: draw anything session-coloured in the city through `ink()` + `glowBlend()` (env.ts), never raw additive, or it shows white on the light day city.
- A session running a command sits on an external (`tt` 3, the shell) in `world.working`/`lastPlace`, so anything that shows sessions on code (domain isles) must fall back to its last file/module event (`codeAtWork()` in cityview.ts) or it goes blank whenever the session isn't editing. The domain map follows commits, not the clock: a watcher on the git dir (`watchCommits`/`checkCommits` in domain.mjs, kv `domain-auto:<pid>`) updates only when the diff since the map's commit adds/deletes/renames a code file or touches a declaration line (`DECL`); uncommitted work never counts. Don't bring back a Rebuild button or time gaps.
- The frame cityview hands the layers (`setFrame`) still contains the floating pulse bar, layer thumbnail and compass — HTML labels placed "inside the frame" land under them; on the domain map keep clear of `DomainMap.occluders`.
- Saturated colours in the 3D scene come out pastel by default: ACES tone mapping plus the pale day fog wash them out (a 0.45-lightness blue rendered near white). For a colour that must stay vivid (district borders), use `MeshBasicMaterial` with `toneMapped: false, fog: false`. `AdditiveBlending` and emissive-only glows (night-era selection arcs, lit streets) vanish on the day scene — draw fat `LineSegments2` on a white casing, and tint `diffuseColor` by day.
- Task board (`server/board.mjs`, `web/src/board.ts`, table `board`): one Haiku call splits a pasted list into tasks only across projects (same-project parts are merged back; a project name is also often a plain word, e.g. "voice"; each part gets the whole message) (`group`, `after` = waits for another task, whose folder it gets via `--add-dir`) and routes each to a project, runs it via `runAgent({tools:'task'})` (edits accepted, commands need an `allow` rule, `resume` continues the session), and turns report `asks` + Claude's `permission_denials` into the user's to-do. Before the first run a Haiku `planFor()` decides one piece vs steps (`t.steps`, `after` per step), so planning doesn't depend on the working model; each step is one resumed turn (`pickStep`/`afterStep`), asks carry `step`, answers are sent once (`a.sent`), `pause` stops after each step (state `paused`). Test it on a copied DB (`VACUUM INTO`, `CODETYCOON_DB`, port 4401, `CODETYCOON_OPTIMIZE_MODEL=haiku`), never the real board.
- After server `.mjs` changes, restart :4400 yourself (a built UI against the old server 404s on new routes): stop the node listening on 4400, then `wscript "%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\CodeTycoon.vbs"` (hidden, logs to `~/.codetycoon/server.log`, outlives the session).
- Playwright element screenshots of overview sections come out blank below the fold (`.overview` is its own scroll container) — `scrollIntoViewIfNeeded()` then take a page screenshot.
- A popup placed inside the project header (`.topbar.glass`) drew under the pulse strip and map labels — put popups on `<body>` with `position: fixed` and place them from the anchor's `getBoundingClientRect()` (as `voice.ts` does).
- Voice control (`server/voice.mjs`, `web/src/voice.ts`): Deepgram key in `~/.codetycoon/deepgram` (never the repo). Nova-3 takes `language=en|ru|he`; `detect_language=true` can't be limited to a list (`detect_language=en,ru` → 400), so Auto falls back to English. Test board actions on a copied DB with `auto=0`, or a voice "add" starts a real session.
- Windows can't rename a folder while any process holds a file in it, even a test's own unclosed `DatabaseSync` (the data-dir move silently fell back to the old folder) — close handles and stop the server before testing a move.
- Board tasks in git projects run in worktrees (`server/worktree.mjs`, `<repo>/.claude/worktrees/task-<id>`, folded into the project by `norm()`). With `core.autocrlf=true` even a `git merge` git refuses rewrites the user's dirty files to CRLF — check overlap with `git status --porcelain` first (untrimmed: the status code starts with a space). Junctions to ignored folders must be unlinked before any recursive delete of a worktree.
- `gh` (GitHub CLI) is not installed here — open PRs from the link `git push` prints. Switching the checkout back to `main` after pushing a branch takes the running app's code out from under it (the server and `dist/` run from the working tree); stay on the branch until it is merged.
- Account plan limits (`server/limits.mjs`, pulse key `limits`) read `api.anthropic.com/api/oauth/usage` with Claude Code's own OAuth token — never refresh that token (it rotates the refresh token and logs Claude Code out). A fetch started during the server's startup backfill stalled forever and froze the numbers; keep the 30 s inflight drop and the route's race timeout.
- Setup sync (`server/setup/`, `code-tycoon audit|snapshot|restore`, format in `docs/setup-snapshot.md`): file classes come from per-tool adapters in `setup/adapters/`; add a tool or a path there, not in scan/snapshot. Test restore with `USERPROFILE`/`HOME`/`APPDATA` = a scratch fake home and `CODETYCOON_PASSPHRASE`, never the real home; a test snapshot writes `~/.codetycoon/setup-last.json`, delete it afterwards or the audit reports a scratch folder as the last snapshot. Plan and later phases (container, accounts) are outside the repo in `../Visualizer-plans/setup-sync.md`.
- `code-tycoon protect` (`setup/protect.mjs`, state `~/.codetycoon/protect.json`, guard every 5 min from index.mjs) must never push to a person's existing branches: on a remote it didn't create, only `refs/codetycoon/backup|wip/*`. Test it with `protect-fixture`-style fake homes and `--to <folder>` (bare repos), never on real projects; a fake home under Temp is allowed by `knownRoots()` only because the home itself is under Temp. GitHub device flow needs `CODETYCOON_GITHUB_CLIENT_ID` until the App is registered.
- `git fetch -q -c http.extraheader=... origin` silently fails (`-c` is not a fetch option): protect's fetch after the first push did nothing and the branch showed `[gone]` — `gitAuth()` args go before the subcommand: `git -c ... fetch`.
- `wsl -l` hangs and Docker Desktop reports "unable to start" on this machine (2026-11-20) — don't block on them; run long checks in the background, and test Linux restores with `planRestore(..., { platform: 'linux', home: '/home/x' })` + `contentOf()`.
